# Security Policy

## Supported scope

Security reports are welcome for the public website source, its JavaScript, GitHub Actions workflows, deployment configuration, and any feature that could expose sensitive data or allow unintended control of the site.

## Reporting a vulnerability

Please do not publish active security vulnerabilities in a public issue.

Use GitHub's private vulnerability reporting feature from the repository **Security** tab when it is available. If private reporting is not enabled, contact the repository owner through GitHub and provide enough detail for a private response.

Please include:

- affected file, URL, workflow, or feature;
- clear reproduction steps;
- security impact;
- suggested mitigation, when known;
- screenshots or logs only when they do not expose secrets or personal data.

## Handling principles

We will prioritize reports involving credential exposure, unauthorized modification, cross-site scripting, unsafe redirects, workflow compromise, supply-chain risks, or accidental exposure of personal/clinical information.

Do not include patient identifiers, medical records, API keys, access tokens, passwords, or other confidential information in issues, pull requests, or public logs.

## Disclosure

Please allow the maintainer reasonable time to validate and remediate a report before public disclosure.
